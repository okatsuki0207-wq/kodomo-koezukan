# こえのずかん — Firebase設定

## 費用について
Cloud Storage for Firebaseは現在Blazeプランと課金アカウント登録が必須です。
無料枠はありますが、リージョン・使用量で料金が発生します。
新規StorageバケットのAlways Free対象はUS-CENTRAL1 / US-EAST1 / US-WEST1です。
地域を選ぶ際は、子どもの写真・声の保存場所も検討してください。
予算アラートは利用や課金を停止する上限設定ではありません。
公式情報: https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024

## 設定手順
1. Firebase Consoleでプロジェクトを作成し、Webアプリを登録する。
2. プロジェクト設定のWeb用 `firebaseConfig` を `src/firebaseConfig.ts` にコピーする。
   SDKはFirebase 12（v9以降のmodular API）。Web設定は公開情報です。
   サービスアカウント秘密鍵をフロントエンドに置かないでください。
3. Authentication → ログイン方法 → 匿名を有効化する。
4. Authentication → 設定 → 承認済みドメインに開発・公開サイトの実際のホスト名を登録する。
5. Firestore Databaseを作成する。`firebase/firestore.rules` の内容をルール画面で公開する。
6. Blazeの料金条件を確認し、自分で有効化したうえでStorageを作成する。
   `firebase/storage.rules` の内容をルール画面で公開する。
   両方のルールは認証UIDごとに分離し、未認証ユーザーや他人のデータアクセスを拒否します。
7. サーバーを再起動して、写真・声の保存、ページ再読み込み、再生、削除を実際のプロジェクトで確認する。
   Storage/Firestoreの設定が無い状態では、クラウド保存はできません。

## 保存内容
- 使用するバケットは `kids_voice_zukan`。初期化時に `getStorage(app, 'gs://kids_voice_zukan')` として明示しています。
- Storage: `users/{uid}/keepsakes/{cardId}/photo` と `voice`。ファイルのContent-Typeを保存。
- Firestore: `users/{uid}/keepsakes/{cardId}`。
  名前、画像/音声ダウンロードURL、ファイルパス、サーバー作成日時、選択したカテゴリIDを保存。
- ユーザーが追加したカテゴリ: `users/{uid}/categories/{categoryId}` に名前と作成日時を保存。
- 一覧はFirestoreのリアルタイム購読で更新。LocalStorageへの書き込みはありません。

## カテゴリ（ページ）機能の有効化

カテゴリ機能を追加した後は、**Firestoreのルールを更新して公開**してください。
Firebase Console → プロジェクト `klds-voice-zukan` → Firestore Database → ルールで、
`firebase/firestore.rules` の内容を貼り付けて「公開」を押します。
コード内のファイルを更新するだけではFirebase側のルールは変わりません。
Storageのルール変更やファイルの再アップロードは、この機能のためには不要です。

- 「おもちゃ」「どうぶつ」「さくひん」は最初から表示される既定カテゴリです。
- 追加カテゴリは認証UIDごとにFirestoreへ保存され、再読み込みしても維持されます。
- 既存カードには勝手にカテゴリを割り当てません。「すべて」から名前をタップして詳細を開き、
  編集でカテゴリを選べます。未分類に戻したカードも「すべて」に表示されます。
- 編集では名前・カテゴリだけを更新し、写真・音声・ファイルパス・作成日時は維持します。
- 名前は24文字以内です。「すべて」や既定カテゴリと同じ名前の追加はできません。
  前後の空白・全角英数字・英字の大小を正規化した同名カテゴリは重複しません。
- カテゴリ名の変更・削除、複数カテゴリへの同時所属、利用者間の共有は今回の機能には含めません。
- ルールが未更新のときは、カテゴリ一覧の購読・追加や分類を伴う保存で権限エラーになります。
  全員公開ルールに変更して回避しないでください。
- 画像加工は従来どおり最大600px。透明画像はPNG、不透明画像はJPEG品質0.75。
- 録音終了後、AudioContextでデコードして10ms窓のRMSを解析。
  閾値0.01（-40dBFS）を2窓連続で超えた開始位置の約0.05秒前までを削り、
  PCM 16-bit WAVで保存する。末尾や内部の無音は削らない。
  `src/lib/audioTrim.ts` の定数で閾値・余白を調整できます。
  全無音・デコード失敗は明示的なエラー。未処理音声を黙って保存しません。
  録音はメモリ消費とファイルサイズを抑えるため最大60秒です。
- 音声の冒頭無音は短縮されますが、初回ダウンロードの通信時間は発生します。

## パスワード付き共有

- 持ち主が「共有」から明示的に作成したときだけ、別の共有コピーを作ります。元の写真・音声を共有用に公開することはありません。
- カード情報・画像・音声はブラウザ内で暗号化してから保存します。共有パスワードはFirebaseへ送信・保存しません。閲覧用URLは暗号化キーを含まず、パスワードはURLとは別の経路で伝えてください。
- パスワードは16〜128文字です。推測されにくい言葉を複数つなげてください。忘れた場合は復元できません。すでに閲覧者が保存したデータは、共有を停止しても取り消せません。
- 1つの共有に最大250件、1ファイル20MB未満、合計200MBまでの複製を作ります。共有分のStorage使用量と通信量も発生します。
- 有効な共有の暗号化データは、パスワードなしでは内容を読めませんが、共有リンクを知る人は暗号化データを取得できます。推測されにくいパスワードを使い、リンクと別に伝えてください。
- 共有を有効にするには、`firebase/firestore.rules` と `firebase/storage.rules` の両方をFirebase Consoleへ公開してください。元データの `keepsakes` ルールは変更しないでください。
- 多数の一般ユーザー向けに公開する前に、サーバー側のアクセス制限、不正利用監視、通信量・Storage費用の制御を追加で設計してください。

## 旧データの移行
旧LocalStorageデータがあるブラウザには「Firebaseへ移行」を表示します。
設定完了後に押すと、画像と音声をStorageへアップロードし、カードをFirestoreへ移します。
旧データは読み取り専用で、削除・書き換えしません。通常保存の代替として使うこともありません。
再試行は同じIDを使い、既にFirestoreにあるカードはスキップします。
旧音声は元のまま移行し、新しい録音だけを自動トリミングします。
クラウド側を削除しても旧バックアップは残るため、移行ボタンを再度押すと再インポートされます。
データ移行と再生を確認した後、不要なら自分で旧ブラウザデータを削除してください。

## Google Cloud Consoleで作成したバケット
未使用ファイルの確認・個別削除の保持条件と、公開前のルール更新については
`firebase/TESTING.md` の「未使用ファイルの確認・個別削除」を参照してください。
保存結果不明・旧形式のファイルは日数だけで未使用と判断して削除しません。

詳細な切り分けとCloud Shellコマンドは `firebase/STORAGE_TROUBLESHOOTING.md` を参照してください。
`kids_voice_zukan` は対象Firebaseプロジェクトに関連付けて利用してください。
GCSに作成しただけではFirebase SDKから利用できるとは限りません。
Firebase ConsoleのStorageで既存バケットを取り込み、Firebaseのサービスエージェントに必要な権限を付与し、
このバケットにも `firebase/storage.rules` を公開してください。
全員公開のIAM権限や、全員読み書きできるルールに変更しないでください。
公式手順: https://firebase.google.com/docs/storage/web/start#working_with_imported_buckets
すでに旧バケットに保存したカードは、元のダウンロードURLを使って読み込みます。
今回の変更では既存ファイルのコピー・削除・Firestore内のURL書き換えは行いません。

## 匿名アカウントの注意
匿名認証のIDだけをIndexedDBで維持します。写真・音声・カードはFirebaseに保存します。
別端末には自動共有されません。ブラウザデータを消すと匿名アカウントを失い、
クラウドに残るデータへアクセスできなくなる場合があります。
継続利用・端末間共有には、匿名アカウントに通常のログイン方法をリンクする追加対応が必要です。
オリジナルのStorageダウンロードURLはURLを知る人が閲覧できるため公開しないでください。
パスワード共有では、オリジナルURLではなく別の暗号化コピーだけを使います。

## エラー・削除
保存完了の応答を受け取るまで入力を保持し、二重保存操作を抑止します。
通信障害で結果が不明な場合はアップロード済みのファイルを勝手に削除せず、
一覧を再確認する案内を表示します。未使用ファイルが残る場合はConsoleから確認できます。
削除は写真・音声を削除してからカードを削除します。
部分失敗ではエラーを表示してカードを残し、再実行できます（既に消えたファイルはスキップ）。
FirestoreとStorageを跨ぐ処理は原子的ではありません。
