# Webアプリ（「こどもの こえずかん」）全面改修・UI/UXリファクタリング・バグ修正指示書

提供中のWebアプリについて、コードベースおよびUI/UXの全体的なブラッシュアップを実施してください。以下の要件定義に従い、デザインの整頓、レイアウト再設計、バグ修正、および新機能（ガイドボイス）を実装してください。

---

## 1. ファーストビューおよびレイアウト全体の再構築

画面を開いた際、ユーザーが迷わず自分の図鑑コンテンツにアクセスできるよう、レイアウトの優先順位を組み替えてください。

### 【削除・非表示要素】
* 画面内の「わが家のずかん」という大きなタイトルテキストを削除してください。
* デバッグ・開発用UI（「保護者向け：未使用ファイルの確認」ボタン、および「旧データが〇件あります...Firebaseへ移行」などのデモ用バナー領域）をコンポーネントおよび画面から完全に除去してください。

### 【ヘッダー・ファーストビュー領域】
* **コンパクトヘッダー化:** 画面最上部にコンパクトなヘッダー領域（`height: 60px` 程度）を配置し、アプリタイトル「こどもの こえずかん」のロゴおよびシンプルなアイコンのみを配置してください。
* **新規作成UIの小型化:** 現在ファーストビューの大半を占めている「カード作成」エリアを縮小し、ヘッダー右上のコンパクトなボタン、または画面右下に追従するフローティングアクションボタン（FAB / `position: fixed`）へとデザイン変更してください。
* **メインコンテンツ（図鑑優先）:** 画面の縦幅の大半を図鑑カードグリッド（一覧表示）に割り当て、アプリ起動時に即座に録音カード群が目に入る構造にしてください。

---

## 2. デザインのトータル調整（余白・タイポグラフィ・視覚的整合性）

機能追加により散乱したデザインパーツを整理し、全体的な統一感を持たせてください。

### 【デザインシステム・余白の整頓】
* **余白（Spacing）の統一:** コンポーネント間の余白を8pxベース（8px, 16px, 24px, 32px）で再定義し、バラバラになっている `margin` / `padding` を調整してください。
* **注記・補足文のグループ化:** カード内やモーダル内に配置されている小さな補足文（例：「※録音した声は後から図鑑カード長押しで編集できます」等）は、関連する操作ボタンのすぐ下（`margin-top: 4px`〜`8px`）に適切な文字サイズ（`font-size: 0.75rem / 12px` 程度、控えめなグレーカラー）で配置し、主操作を邪魔しないデザインにしてください。
* **カードタップ時のインタラクション:** 
  * 青いデフォルトの枠線（Outline）を削除してください。
  * タップ時にカードが拡大＆揺れるアニメーションは維持しつつ、タップされたカードの位置からパステルカラーの音符パーティクル（♪, ♫）がふわふわと上部に浮き上がって消えるCSS/JSアニメーションを追加してください。

## 3. 音声ファイル読み込みバグの修正（波形編集画面）

カード長押しメニューから「波形カット編集」を選択した際に発生する「ファイルを読み込めませんでした」エラーを解消してください。

### 【原因箇所の修正指示】
1. **データ構造とURL参照の確認:** カードオブジェクト内に保存されている音声データ（`Audio Blob` または `Base64 / ObjectURL`）の参照パスが、モーダル起動時に正しくWaveSurfer（または使用中の波形描画ライブラリ）に渡されているかデータフローを点検してください。
2. **非同期ロード処理の安全化:** 
   * モーダル描画のHTML生成（DOM展開）と、波形ライブラリへのデータロードのタイミング非同期ズレを防ぐため、`DOM展開完了後（`setTimeout` や `nextTick` 等）` に音声データをパース・ロードするように処理順序を保証してください。
   * `URL.createObjectURL` を使用している場合は、メモリーリーク対策を施しつつ適切な Blob URL が生成されているか検証してください。

## 4. ガイドボイス（キャラクターボイス）機能の実装

録音ボタンを押した際、システム音「ピコン」の代わりに、キャラクターのガイドボイス「これはなーに？」を再生する処理へ置き換えてください。

### 【仕様・動作フロー】
1. **音声ファイルの用意:** `/assets/audio/voice_what_is_this.mp3` にキャラクターボイス（「これはなーに？」）を配置できる構造を用意してください。
2. **イベントハンドラーの改修:**
   * ユーザーが「録音開始ボタン」をタップした際、即座にマイク録音を開始するのではなく、まずガイドボイス `voice_what_is_this.mp3` を再生させてください。
   * ガイドボイスの再生終了イベント（`ended` イベント）を検知した直後、または音声再生終了から数百ミリ秒後に、自動的にマイク録音（`MediaRecorder.start()`）を起動する非同期処理を構築してください。
3. **視覚的フィードバック:** ガイドボイス再生中は、画面上のキャラクターアイコンやボタンに「しゃべっている（発話中）」アニメーションを付与し、マイク録音中（「聴いている」状態）との違いを明確に提示してください。
